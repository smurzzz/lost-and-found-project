We are designing "ClaimIt", a modern MOBILE APPLICATION for Android — a school Lost & Found system built around a QR-CODE-VERIFIED CLAIMING PROCESS.

IMPORTANT DESIGN DIRECTION:
Use the attached reference image as the PRIMARY VISUAL INSPIRATION for the UI style, composition, spacing, cards, and overall aesthetic.

The final design should feel like a polished modern startup/mobile product, not a generic school management system.

VISUAL STYLE:
- Clean, minimal, premium mobile UI
- Soft, calm, friendly, trustworthy aesthetic
- Inspired by the reference: rounded smartphone-style layouts, floating cards, soft shadows, large rounded corners, subtle depth, clean white surfaces, and generous whitespace
- Use slightly off-white/light gray backgrounds instead of pure white everywhere
- Use rounded cards and containers with approximately 16–24px corner radius
- Use subtle shadows and elevation to create depth
- Use large, visually appealing item thumbnails/photos
- Use simple outlined icons with consistent stroke weight
- Avoid overly dense dashboards
- Avoid excessive borders and unnecessary decorative elements
- Use clear visual hierarchy with large headings and compact supporting text
- Keep everything optimized for one-handed mobile use
- All important buttons and touch targets should be at least 48px
- 16px horizontal page margins
- Single-column mobile layouts
- Bottom navigation should look modern and floating/soft, inspired by the reference
- Use subtle micro-interactions and selected states
- Maintain strong accessibility and readable contrast

COLOR PALETTE:
Primary Navy: #172554
Dark Navy: #0F172A
Emerald: #10B981
Light Emerald: #D1FAE5
Amber: #F59E0B
Light Amber: #FEF3C7
Neutral Background: #F5F7F8
Card White: #FFFFFF
Primary Text: #0F172A
Secondary Text: #64748B
Border/Divider: #E2E8F0
Muted Gray: #94A3B8

COLOR USAGE:
- Navy = primary structure, headings, navigation, primary buttons
- Emerald = verified, claimed, successful, released states
- Amber = pending matches and pending claims
- Gray = searching, unclaimed, default states
- Red should only be used for destructive actions such as Log Out confirmation
- Do not make the entire application dark navy
- Keep the overall interface light, airy, and soft

TYPOGRAPHY:
Use Inter throughout.
- Large bold headings
- Medium-weight section headings
- Regular body text
- Small muted metadata
- Avoid excessive uppercase text
- Keep typography simple and highly readable

BRAND:
App name: ClaimIt
Tagline:
"Lost something? Found something? Let's get it back."

The app's main visual identity should communicate:
TRUST + VERIFICATION + SIMPLICITY + RECOVERY

Do NOT include:
- AI photo matching
- AI-generated matching visuals
- SMS/text messaging
- Emergency contacts
- Social/community features
- Scoring systems
- Ranking systems
- Gamification
- Unattended self-service pickup
- Manual email/password login
- Accessibility settings screen
- Complex analytics charts
- Excessive admin-dashboard style layouts

CORE CONCEPT:
Every found item is logged by Staff and automatically receives a unique QR code/tag.

A student can submit a claim, but an item can ONLY be marked "Claimed" or "Released" after a Staff member scans the item's QR code and confirms the release.

USER ROLES:
1. STUDENT
- Report lost items
- Browse found items
- Receive possible match notifications
- Submit claims
- Track claim status
- View profile

2. STAFF
- Log found items
- Generate QR tags
- Scan QR codes
- Review pending claims
- Confirm item releases
- View chronological audit history

- Very subtle shadows

Buttons:
